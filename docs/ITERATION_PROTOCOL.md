# 猫思之项目迭代规范（ITERATION PROTOCOL）

生效日期：2026-10-18。适用范围：本项目所有后续技术改进、bug 修复、功能新增。
本规范由用户在「五任务优化」迭代中明确要求建立，本轮即作为首个执行实例。

---

## 一、标准流程（必须按序执行）

```text
1. 实施计划报告
      ↓
2. 子代理审计（必须提出 ≥5 个验证问题）
      ↓
3. 问题校验（回答/取证每个问题，确认迭代方向无重大偏差）
      ↓
4. 用户审批（明确批准后才开始落地）
      ↓
5. 开发与测试运行
      ↓
6. 审计报告（交付物清单 + 测试证据 + 遗留项）
```

任何一环未完成，不得进入下一环。紧急 hotfix 也不例外；可以压缩文档篇幅，但不能跳过审计与审批。

## 二、实施计划报告要求

存放路径：`docs/iterations/<日期>-<主题>/实施计划报告.md`

必须包含：
1. **背景与证据**：问题现场、日志/数据证据、文案与代码映射；只写已核实事实，标注假设。
2. **方案**：每个任务的改动点、影响面、不做什么（明确排除项）。
3. **验证标准**：合成回归、浏览器专项、真实验收各自的通过条件。
4. **风险与回滚**：每个风险给出应对；改动必须可单独回滚。
5. **交付物清单**：文档、代码、证据目录。

## 三、子代理审计要求

- 审计者：独立子代理，只读审计，不改代码。
- 审计内容：抽样核对计划中的事实断言（属实/不属实/部分属实 + 证据）；指出遗漏、错误假设、风险低估。
- **必须提出 ≥5 个验证问题**：问题需具体、可回答、能暴露隐藏假设；每个问题附预期答案方向或验证方法。
- 计划编制者必须逐条回答（取证或安排验证），并把问答记录补入计划报告。

## 四、审计报告要求（落地完成后输出）

存放路径：与计划报告同目录，`审计报告-<主题>.md`

必须包含：
1. 实际修改文件清单（逐文件链接 + 修改要点）。
2. 测试结果：合成回归（通过数/总数）、规范检查、构建、浏览器专项；附证据文件路径。
3. 与计划的偏差：任何临时调整及理由。
4. 遗留项与后续建议；失败事实如实记录，不粉饰。

## 五、项目红线（任何迭代不得违反）

1. 不改动 UI 结构与交互逻辑，仅做视觉风格替换——用户显式授权的功能改造除外。
2. 密钥、Token 不落仓库、不写入报告与日志。
3. AI 预算硬上限（当前：4096 输出词元/次、24 次调用/任务、10 万字符输入）不放宽。
4. 失败事实不粉饰；「未验证」不得写成「已通过」。
5. 文档导入优先选用生产验证过的开源组件；大文件流式解析；多文件队列处理。
6. 改造完成后先由用户手动测试，再执行全量自动化回归。
