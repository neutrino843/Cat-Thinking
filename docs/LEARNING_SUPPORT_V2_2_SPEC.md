# V2.2 分层提示与自我解释闭环

状态：第一阶段已实现｜日期：2026-10-15

## 1. 要解决的问题

现有 AI 学习辅助已经能限定原文范围，并区分解释、比较、提示、反馈、目标、变式和补充整理，但不同模式仍像一组并列生成按钮：

1. 学习者可以直接索取完整解释，系统没有明确的提示递进路径。
2. 提示请求不能利用“我已经想到什么”定位卡点。
3. 同一个尚未查看的请求可能被重复准备，增加重复任务和误触付费风险。
4. 默认选中前 20 个来源；当字符数超过 24,000 时只禁用按钮，需要用户手工修改数字范围。
5. `learnerAnswer`、`hintLevel`、`quizType` 和 `difficulty` 在数据结构上都是可选字段，旧实现会把不属于当前模式的残余字段继续发给服务端。

## 2. 下一功能定义

下一功能是“分层提示与自我解释闭环”。目标是在给出答案前尽量保留学习者的主动回忆，同时让确实卡住的用户能够逐级获得帮助。

### 2.1 帮助阶梯

| 层级 | 输出边界 | 学习者动作 |
| --- | --- | --- |
| 第 1 级：定位概念 | 只指出一个关键概念或前置知识，并问一个引导问题；不给答案或完整步骤 | 补充自己的当前想法后再次尝试 |
| 第 2 级：推进一步 | 结合学习者已写内容指出下一个缺失推理步骤，并问一个针对性问题；仍不给最终答案 | 完成剩余推理或作答 |
| 第 3 级：完整解释 | 给出有原文依据的完整解释，然后提出一道关闭解释后可以回答的短回忆题 | 关闭解释后重新回忆或独立作答 |

只有状态为 `viewed` 或 `accepted` 的提示记录才推进建议层级。仅准备、仍在生成、失败或已拒绝的记录不推进。

### 2.2 自我解释

- “检查我的理解”继续要求填写自己的解释。
- “给我提示”增加可选的“我已经想到的内容”，用于定位卡点。
- 学习者文字只作为待分析内容，不作为证据，也不能覆盖系统规则、预算或引用约束。
- 查看第 3 级完整解释后的后续作答必须保留“使用过完整解释”的辅助事实；不能计为独立掌握证据。

### 2.3 原文范围

- 仍只发送用户当前选择的归档原文。
- 默认范围按原顺序自动截到 24,000 字符以内，最多 20 个片段。
- 用户可以继续调整每个片段的起止位置；超限和非法范围仍阻止准备。

### 2.4 防重复与付费边界

- 相同模式、知识范围、原文范围、问题、学习者文字和参数的 `prepared` 记录直接复用。
- 已查看、已接受或已拒绝的记录不会被静默复用；后续若支持重新生成，必须提供显式按钮并说明会产生新调用。
- 准备记录不调用模型；“确认并生成”仍是唯一正式生成入口。

## 3. 模式契约

| 模式 | 必需字段 | 可选字段 | 禁止字段 |
| --- | --- | --- | --- |
| `hint` | `hintLevel` | `learnerAnswer` | `quizType`、`difficulty` |
| `feedback` | 非空 `learnerAnswer` | 无 | `hintLevel`、变式字段 |
| `variation` | `quizType`、`difficulty` | 无 | `learnerAnswer`、`hintLevel` |
| 其他模式 | 问题与原文范围 | 无 | 上述模式专属字段 |

客户端准备阶段与服务端分析契约使用相同规则。读取旧记录时允许兼容，但生成前只构造当前模式需要的字段，避免残余数据泄漏到提示词。

## 4. 第一阶段实现

- `nextHintLevel`：按知识/题目范围和已查看记录建议 1–3 级提示。
- `defaultSupportScope`：把默认原文范围限制在 24,000 字符内。
- `supportGeneration`：按模式重建最小请求，不透传无关可选字段。
- `prepareLearningSupport`：校验模式字段并复用相同的未完成准备记录。
- `analysisOptionsSchema`：服务端入口拒绝字段组合不一致的请求。
- 提示 UI：显示建议层级、各层输出边界和可选的已有思路。

## 5. 后续阶段

### 第二阶段：重新作答闭环

- 第 3 级解释后直接进入同题或等价题重新作答。
- 将提示次数、是否看过完整解释和是否回看原文写入对应 `PracticeAssistance`。
- 独立作答与辅助后作答分开展示，不把辅助后正确合并为独立成功。

### 第三阶段：反馈到补学

- 结构化呈现“已有依据、缺失要点、不确定处”，不自动给分。
- 学习者确认后才把反馈关联到评估事件。
- 连续卡在同一前置知识时建议回到原文或前置知识点，不自动修改课程目标与复习日期。

## 6. 非目标

- 不计算掌握率、遗忘概率或能力分数。
- 不让模型自动决定学习者是否通过。
- 不自动升级提示层级或后台生成。
- 不把学习者文字当作来源证据。
- 不在本轮引入云同步、推荐模型或额外供应商。

## 7. 验收标准

1. 新提示默认从第 1 级开始；查看第 1、2 级后分别建议第 2、3 级，准备但未查看不推进。
2. 第 1、2 级系统指令明确禁止最终答案，第 3 级包含一次短回忆检查。
3. `hint`、`feedback`、`variation` 的必需字段与其他模式的禁止字段在客户端和契约层同时生效。
4. 30,000 字符的单一来源默认只选 24,000 字符，界面无需用户先修正才能准备。
5. 完全相同的 `prepared` 请求返回同一记录，不新增文档或生成任务。
6. 准备与浏览已有记录不产生 POST 生成请求。
7. 旧课程包仍能读取；旧记录中的无关字段不会进入新的模型请求。

## 8. 验证计划

- 规则单测：层级推进、范围截断、字段清洗、重复复用和非法组合。
- 契约/服务测试：跨字段约束、三层提示指令、学习者内容不提升为系统指令。
- 浏览器测试：选择提示、填写已有思路、默认范围不超限、准备阶段无模型调用。
- 完整门槛：`check:ci`、Chromium 回归、`git diff --check`。
