# 猫思之的产品方向

**能回到原文的学习工作台。理清知识，测出疑问，回到原文。**

主要服务课程学习、考试复习与实验理论整理。产品围绕“自己的资料 → 可编辑的知识结构 → 自测 → 回看题目与原文 → 修改自己的理解”发展。学习效果需要真实用户验证，不能承诺提高成绩、保证结论正确或用一次自评推断掌握程度。

## 当前可使用的流程

学习首页以个人当天总时间和题量为上限，在多门课程之间安排续学、到期复习、补学和新学习。用户可以查看未安排任务及原因，调整容量后重新计算；示例课程、阅读、计划和本地练习不调用模型。

课程工作台提供目标、资料、知识、练习、备考、应用任务、记录和备份。目标范围由用户确认后生效；资料、练习覆盖和学习观察分别展示证据。引导学习会话保存步骤、回忆文字、停留位置和暂停状态，刷新或关闭后可继续，来源或目标版本变化时要求重新核对。

练习保留每次提交、提示和答案揭示记录；回忆卡片、模拟练习和应用自评使用不同证据口径。课程可以按确认目标和题型要求组卷，题库不足会保留缺口，不用其他题型或重复题目凑数。课程包可恢复目标、归档、会话、作答、评估和辅助记录，并为恢复后的实体重建独立身份。

需要 AI 帮助时，用户明确选择当前知识点、原文范围和用途，再进入现有生成确认流程。解释、比较、提示、反馈、目标建议、变式和补充整理都创建独立任务；旧任务与归档不会被改写。文档编辑、作答、自评、计划、示例和结果查看不新增生成调用。

## 后续开发顺序

| 阶段 | 新价值 | 必须满足的边界 |
| --- | --- | --- |
| AI9.1 引用可靠性 | 将程序管理的依据编号贯通五类内容草稿与修复 | 保留旧任务提示版本与结果格式，继续严格校验；真实验收另行授权 |
| AI9.2 知识与练习联动 | 从知识节点查看相关题目、本次反馈与原文 | 同一任务的明确身份映射；共同依据只表示相关，不等于因果或掌握状态 |
| V2 P0/P1 学习闭环 | 目标、可恢复会话、跨课程计划、上下文辅导、回忆卡片、备考与证据视图 | 本地流程与课程包已实现；真实模型语义质量仍需授权样本验收 |
| AI9.4 Windows 安装与升级 | 新电脑安装后打开使用，升级和异盘备份保留资料 | 沿用本机 PostgreSQL，运行环境自动准备；当前 CMD 仍是开发工作区入口 |

当前不计算知识掌握率，也不把一次答对、自评、看过答案或使用提示后的作答当成独立掌握证据。跨资料同名知识不会自动合并。多用户、云同步、联网搜索、通用安装包、后台付费生成和基于长期历史的自适应算法仍需独立立项与验证。

## 代码和数据约束

- 复习、跨课程容量、目标覆盖和会话推进分别放在可测试的规则模块中；UI 负责呈现，仓库层的事务、版本比较和身份校验负责保存与冲突处理。
- 练习绑定文档、任务、产物、产物哈希与来源指纹；原文或身份失效时停用旧内容。知识映射使用明确 ID 和版本，不按标题相似度猜测。
- 会话绑定目标版本、知识点修订和归档哈希；暂停、恢复、课程包导入和多页面写入均不得覆盖较新的记录或触发历史模型任务。
- 快捷目标和手动选择共用产物依赖与服务能力检查，不静默改用户选项、不自动追加付费工作。
- Prompt、Provider、coordinator、validator、JobStore、dispatcher 保持各自职责；修复调用独立记账，未知付费结果不重发。
- 密钥沿用服务端加密存储，不进入浏览器持久化、资料包、诊断和日志。
- 不降低现有类型、代码规范、覆盖率、构建大小或恢复验收门槛；普通 CI 继续使用 fake Provider 与公开或脱敏 fixture。
- 本机个人连接可用不代表公众发布通过；未取得目标环境的完整 store、Provider、dispatcher、usage 与 recovery 证明时，公众 `acceptsRuns` 保持关闭。

## 定位依据

来源驱动的测验、可编辑 AI 导图、主动回忆与间隔复习已有其他产品实践，不宣传单项能力或其组合为市场独有。猫思之需要验证的是：中文课程资料中的结构、练习反馈与原文复核能否连贯使用，以及自选模型、保存与恢复是否足够清楚。[NotebookLM 官方说明](https://blog.google/innovation-and-ai/models-and-research/google-labs/notebooklm-app-quizzes-flashcards/)、[Xmind AI](https://xmind.com/ai)、[Anki 官方背景说明](https://docs.ankiweb.net/manual/background)（核验：2026-10-13）。
