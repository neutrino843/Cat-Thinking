# Cat Analysis Service

The user-facing Windows entry is `启动猫思之.cmd` (or `npm run start:local`). It starts the local database, authenticated gateway and AI service in explicit **personal** mode; missing native database binaries/configuration are prepared automatically. The browser's **AI 设置** panel owns provider selection, API key, model discovery/manual entry, connection checks, activation, pause and removal. Instructions for ordinary users are in the repository [README](../../README.md).

`ANALYSIS_OPERATING_MODE` defaults to `deployment`. Personal mode is restricted to a non-production, authenticated loopback service, exact loopback origins, zero trusted proxy hops and a loopback PostgreSQL database. Saving/checking a connection does not generate content. Explicit activation starts the existing coordinator/adapters/validators/dispatcher with immutable run-to-profile bindings and token/invocation limits; personal authorization never fabricates production smoke evidence. Model changes stop old work and revoke its stored credentials while retaining result and usage identities. The independent encrypted profile schema is version 2; the analysis schema remains version 5.

`npm run verify:personal:local` uses `ANALYSIS_PERSONAL_READ_ONLY=true`: it does not dispatch, cancel, revoke credentials, expire content or accept API mutations, even for an enabled saved profile. It may bootstrap or migrate the supported database tables; this is an application read-only probe, not a promise of zero SQL writes. `npm run e2e:personal:local` tests the real settings UI, gateway, PostgreSQL and five-artifact pipeline using test-only fake HTTP and public fixtures. It shares the isolated database lock with the older synthetic runner and must run sequentially.

`npm run verify:personal:provider:local` is a separate **billable** verification command. It refuses before database initialization unless `ANALYSIS_PERSONAL_VERIFICATION_ACK=personal-live-up-to-3` is explicitly present. Obtain authorization for the entire batch before setting it. It uses the already enabled saved profile and a fixed public teaching sample, with the existing coordinator, validators, ledger and a dispatcher restricted to its own run. Evidence, Summary, Outline and any repair share a hard limit of three Provider call attempts, with no transport retry; a failure before sending still consumes an attempt. It never dispatches or deletes old user runs, enables a paused connection, or changes credentials. It deletes only its sample content and retains ledger usage. A 120-second generation cutoff and connection-specific database query/lock timeouts bound common failure paths; cleanup follows the cutoff. Its sanitized result explicitly marks itself as **not a production attestation**. This command is never part of startup or ordinary CI, and it does not replace the protected deployment smoke below.

Windows local development needs no cloud account. From the repository root, run `npm run db:install`, then `npm run db:setup`. This installs pinned PostgreSQL 18.6 native binaries into the sibling `.cat-thinking-postgres` directory, initializes one cluster on `127.0.0.1:55432`, and creates separately owned `cat_analysis_local`, `cat_analysis_test` and `cat_analysis_smoke` databases. Passwords and a persistent content-encryption key are generated automatically and never printed. Windows permissions restrict cluster data, secrets and backups to the current user and SYSTEM. No global PATH, Windows service or firewall rule is changed. An ASCII temporary-directory junction works around Windows PostgreSQL initialization under Chinese paths; actual data stays in the sibling runtime directory. Management commands recreate a missing junction.

The optional `ANALYSIS_PERSONAL_VERIFICATION_REQUEST_LIMIT` can reduce that sample command's limit to 1 or 2 when fewer requests remain authorized. It cannot increase the three-attempt ceiling. `evidenceValidated` records the independently validated Evidence checkpoint; a sample with only that checkpoint is partial, not a passed Summary/Outline verification. Never restart a failed three-attempt command to replenish an existing authorization.

Local commands:

- `npm run db:status` / `db:start` / `db:stop`: inspect, start or stop the project cluster; stopping retains data. Start it again after a Windows reboot; it is not registered for automatic startup.
- `npm run db:test`: run all PostgreSQL integration and coverage checks with the dedicated test role/database. It clears inherited Analysis/Provider environment settings. Recovery tests reject database names other than `cat_analysis_test` and `cat_analysis_smoke` before connecting.
- `npm run db:verify`: physically restart PostgreSQL, verify encrypted content recovery, restore a backup into a temporary database, verify role isolation and service readiness/closed admission, then delete its synthetic content and temporary restore database. Stop local service work before running it because it restarts the cluster.
- `npm run db:backup`: create a custom-format development database dump in the protected backups directory. Preserve `secrets/database.json` separately alongside backups: its encryption key is needed to read restored content. Current backups share the same drive; this does not provide protection against drive failure.
- `npm run dev:service:local`: start just the local service with the development role, persistent encryption key, service-token authentication and exact localhost origins. The local Provider is disabled and release hold stays true, even if external Provider settings exist in the parent environment.
- `npm run dev:analysis:local`: start the database, held service on `127.0.0.1:8787`, and frontend on `127.0.0.1:5173` with the trusted same-origin gateway. Open `http://127.0.0.1:5173` and select **AI 分析**. The panel supports Summary, Outline, MindMap, Quiz and Knowledge, source ranges, progress, citations, recovery, cancellation, deletion and explicit artifact retry. MindMap can create an independent editable document; Quiz supports local practice and rubric self-assessment. With no live Provider configured it shows closed admission; it cannot generate new real results. Ctrl+C stops the owned frontend/service processes while keeping the database and its data available.
- `npm run verify:analysis:local`: temporarily start that same held app, verify browser-supplied identity headers are replaced, `acceptsRuns=false`, and creation returns HTTP 503, then close the owned app processes. Requires ports 5173 and 8787 to be free.
- `npm run e2e:analysis:local`: run the isolated synthetic browser suite against `cat_analysis_test`, on ports 5175/8790. It uses the real PostgreSQL store, coordinator, validators, adapters and dispatcher with a test-only fake Provider. The UI explicitly labels synthetic results; the service accepts only hashes of fixed public synthetic fixtures. A shared PostgreSQL advisory lock prevents simultaneous destructive browser/database runners. The runner clears inherited Provider settings, manages random test credentials, and cleans the dedicated database. It does not create a release proof or enable real admission.

The gateway overwrites authorization and tenant headers, rejects cross-origin/remote requests, restricts routes, bounds JSON sizes and timeouts, and forwards SSE with disconnect cancellation. Its configuration uses server-only `ANALYSIS_GATEWAY_*` variables; tokens never belong in `VITE_*` variables. This gateway serves local single-user development. Public/multi-user deployment still requires a trusted authenticated identity-to-tenant mapping and a deployment-owned gateway. Plain `npm run dev` without gateway settings returns a stable HTTP 503 for analysis; `npm run preview` does not install the development gateway.

The browser stores metadata-only analysis task bindings, MindMap application receipts and Quiz practice answers. Additive IndexedDB version 10 preserves version 9 data and adds permanent document deletion tombstones, blocking late autosaves and attachment writes. Explicit reimport of a deleted native document creates fresh document/node/source/blob identities. Tombstones contain only an ID and deletion timestamp; the guarantee applies to deletions performed after upgrading, because earlier deleted IDs cannot be reconstructed. MindMap application atomically creates a document, remaps node/relation/source identities and commits its receipt. Repeated application returns the existing target and preserves subsequent edits. Native JSON retains versioned node/relation source references; other exports retain their existing format limitations. Quiz answers are bound to the verified Artifact content identity; reset advances the revision, and short answers use rubric self-assessment.

Runs and ledger usage remain authoritative on the server. Native Web Locks serialize task mutations across tabs; browsers without Web Locks fail closed for these mutations. Transaction notifications invalidate other tabs' results, with bounded focus reconciliation as a fallback. Read-only reconnection never repeats a model call. Receiving runs may resume identical UTF-8-safe source parts against matching source snapshots. Unconfirmed creation first uses tenant-scoped request-key lookup; abandonment establishes a permanent durable barrier against a late create, including while admission is held. Artifact read failures are isolated by kind with bounded read-only retries. Source changes hide stale results; deleting analysis copies preserves imported originals. Confirmed tokens, unresolved calls and reserved estimates are displayed separately; estimates are not invoice amounts. See [durable recovery contracts and lock order](DURABLE_RECOVERY.md).

Do not delete or regenerate the runtime's secret file to reset passwords: doing so would lose the encryption key for existing content. Re-running setup reuses the configuration and data. The configured local smoke database does not authorize a real Provider call; the protected smoke opt-in and full Provider configuration are still required. Local PostgreSQL results do not replace Linux container CI or live release evidence.

Independent server-side execution boundary for Cat-Thinking analysis. AI-1 established the secure HTTP boundary. AI-2 adds tenant-scoped durable runs, encrypted source parts, revision compare-and-swap, persisted SSE replay, cancellation, worker leases, and TTL cleanup. AI-3 and AI-4 add the evidence pipeline and validated five-artifact DAG. AI-5 adds the provider-neutral gateway, pre-call budget reservation, metadata-only invocation ledger and instance-local circuit breaker. AI-6 assembles versioned adapters and persistent dispatch behind the release gate and connects all five artifacts to the local product.

Production startup requires `ANALYSIS_AUTH_MODE=service-token`, a token of at least 32 UTF-8 bytes, and at least one exact `ANALYSIS_CORS_ORIGINS` value. The service token is intended to be injected by a trusted same-origin gateway; the gateway must overwrite `Authorization` and `X-Cat-Tenant-Id` instead of forwarding browser-supplied values.

Run `npm run build:contracts`, `npm run build:service`, and `npm run test:service` from the repository root. PostgreSQL integration and adapter coverage run with `ANALYSIS_TEST_DATABASE_URL=... npm run coverage:postgres`. Provider credentials, database URLs, encryption keys, source text, prompts, responses, cookies, and authorization headers must never be logged.

Copy `.env.example` into deployment secret/configuration management; do not commit a real `.env`. `ANALYSIS_TRUST_PROXY_HOPS` must equal the number of trusted reverse-proxy hops and defaults to zero so arbitrary forwarded IP headers are not trusted. `/health` is process liveness. `/ready` also checks PostgreSQL when the durable store is enabled. Analysis API routes require authentication in production.

`ANALYSIS_JOB_STORE=disabled` preserves the AI-1 degraded mode. `ANALYSIS_JOB_STORE=postgres` requires a PostgreSQL URL and a canonical base64 32-byte AES key; production additionally requires database TLS. Migrations use a PostgreSQL advisory lock and refuse schemas newer than the service supports.

Deployment capabilities deliberately keep `acceptsRuns: false` until the configured Provider, PostgreSQL store, dispatcher, usage, recovery and protected live smoke are all ready. Admission reevaluates availability for every request, including shutdown/store failure. With PostgreSQL ready, `supportsSse` and `supportsCancellation` become true. Existing persisted runs can be inspected/replayed before new production runs are accepted.

`ANALYSIS_PROVIDER_MODE=openai-compatible` enables validated configuration for one approved endpoint. The base URL is service-owned, its exact host must appear in `ANALYSIS_PROVIDER_ALLOWED_HOSTS`, and production requires HTTPS. `responses` and `chat-completions` request shapes are supported behind the same domain interface. Redirects are rejected, calls have hard timeout/input/output limits, and provider messages or raw responses are never propagated as service errors.

Provider configuration alone does not activate execution. Startup assembles the Evidence/Artifact runtime and persistent dispatcher when store, Provider and explicit price bounds are configured, but starts dispatch only when the release proof is verified. `ANALYSIS_RELEASE_HOLD` defaults to `true`. Setting it to `false` also requires `ANALYSIS_RELEASE_ATTESTATION_PATH` and `ANALYSIS_RELEASE_PUBLIC_KEY_PATH`, a verified build identity and a matching Ed25519 signature. External retrieval remains disabled.

The versioned `evidence.map@evidence-map-v1`, four `artifact.<kind>@artifact-v1` and `artifact.knowledge@knowledge-grounded-v2` prompts use the invocation coordinator and existing validators. Knowledge inference requires valid Evidence identities and supporting source citations while retaining its inference label. Older results remain readable with a policy notice and never trigger automatic paid regeneration. Source/evidence text is serialized only into user prompts as untrusted data. The adapters supply envelope identity locally and decode bounded schemas. Artifact schemas encode optional properties as null for strict Providers, then normalize only optional nulls before validation. MindMap still depends on a validated Outline; recovering Outline only enables a separate explicit MindMap retry.

Repair uses one independent `structured.repair@repair-v2` invocation with its own stable node and identity. Artifact repair supports malformed structure and grounding validation errors; Evidence repair handles malformed structure, while the existing pipeline validates citation semantics. Oversized output, aborted requests and coordinator errors never cause repair. Both adapters limit repair to the remaining output-token budget and account for it independently. Neither successful nor unknown paid invocations are automatically replayed after a crash; missing outputs fail closed, preserving billing records. Ordinary Artifact retry rejects unknown outcomes, deleted/expired content, held admission, stale revisions and invalid dependencies at the authoritative store boundary.

`JobStore.getRunLedgerUsage(tenantId, runId)` returns a fresh ledger snapshot with known actual tokens, reserved estimated costs, invocation count and unresolved count. PostgreSQL computes it in one MVCC statement; `RunService.getRun` uses this as the authoritative public usage when ledger rows exist, including failed/uncommitted output. It never adds a stored total to itself. Actual cost is omitted because invoice amounts are not reported. Configure positive `ANALYSIS_PROVIDER_INPUT_MICROS_PER_MILLION_TOKENS` and `ANALYSIS_PROVIDER_OUTPUT_MICROS_PER_MILLION_TOKENS` as conservative USD bounds; missing rates leave dispatch unassembled.

The dispatcher discovers queued/planning/mapping/merging/generating runs from PostgreSQL and acquires a persistent `dispatcher:run` lease, while stage workers retain their own fencing leases. Heartbeats, cancellation/TTL watchdogs, execution deadlines and bounded draining govern in-flight work. PostgreSQL first acquisition locks the run row to serialize an absent lease; release expires the lease while preserving monotonically increasing attempts. Ordinary CI uses only synthetic fixtures. PostgreSQL CI adds multi-connection conflict, graph/artifact restart and unknown paid invocation recovery tests.

Run `npm run test:provider:live` only in a protected environment, after the preparation procedure in [PROVIDER_PREPARATION.md](PROVIDER_PREPARATION.md). Preflight requires a fresh, trusted exact-build Ubuntu CI prerequisite signature, `ANALYSIS_LIVE_SMOKE=I_ACKNOWLEDGE_BILLABLE_SYNTHETIC_SMOKE`, exact Provider configuration with `maxAttempts=1`, explicit positive price bounds and outer smoke token/cost limits. The configured store and `ANALYSIS_TEST_DATABASE_URL` must target the same dedicated `cat_analysis_smoke`. Fake recovery/coverage use the separate `cat_analysis_test` supplied by `ANALYSIS_RECOVERY_TEST_DATABASE_URL`; **only that synthetic test database is truncated, never the real smoke ledger**. Supply a stable `ANALYSIS_LIVE_SMOKE_EXECUTION_ID`, external `ANALYSIS_LIVE_SMOKE_CHECKPOINT_PATH` and matching protected signing material. The shared target runner writes a signed checkpoint before content cleanup; interruption or repeated execution with the same nonce never repeats successful or unknown paid calls. The command first runs ordinary gates and isolated PostgreSQL recovery/coverage, then the synthetic pipeline. It never raises configured run budgets or rewrites the configuration used by the proof. Completion requires reconnect, ledger reconciliation and scoped content cleanup. Missing prerequisites stop before network/database access. Do not invoke the live test directly or commit secrets/output.

Both protected live commands require `ANALYSIS_RELEASE_SIGNING_KEY_PATH`, the release output path and trusted public-key path, so recovery has a durable signed checkpoint. The signing key must be Ed25519 and match the deployed public key. Keep it outside service containers and outside tracked files. Signing requires a clean Git checkout. The runner issues an atomic, maximum-24-hour proof only after every gate passes; missing keys block before paid calls. The hold stays unchanged. Proofs bind the exact deployment configuration, including credentials, model, costs, auth, TLS and lease policy. Smoke evidence cannot authorize a different database. `npm run test:provider:target` validates the exact held target with a reusable nonce and signed crash checkpoint, without TRUNCATE, schema migration or global expiry cleanup. It preserves unrelated business content and ledger facts, then cleans only its synthetic run. This separate billable command requires explicit authorization, current schema and the full protected prerequisite set. Never point truncating recovery tests at business content.

`npm run build:service` records commit, compiled service/contracts and lockfile digest in `dist/release-build.json`; startup verifies the digest. Container builds accept `--build-arg ANALYSIS_BUILD_COMMIT=<40-character-commit>`. Builds without a valid commit remain closed. Runtime files must remain immutable after startup. The service rereads its public key and proof for admission, dispatcher acquisition, each Provider transport attempt and the active-run watchdog. Expiry/removal/replacement, store/Provider unavailability and shutdown close admission; in-flight requests receive abort on the watchdog cadence. Already transmitted requests can still be billed, so ledger recovery continues to forbid automatic replay of unknown outcomes. After replacing a held or invalid startup configuration, restart the service to start its dispatcher; a running dispatcher can resume after a temporary valid-proof replacement.

The invocation ledger stores provider/model identifiers, bounded usage, safe failure categories, and timestamps. It never stores source text, prompts, schemas, raw model output, raw provider errors, or API keys. A stale `running` invocation becomes `outcome_unknown` and is not automatically resent because the provider may already have processed and billed it. Automatic retries are bounded and require an explicit confirmed `not_accepted` outcome. Lost responses, ambiguous fetch failures, timeouts and HTTP 408/5xx do not establish that fact. Known usage survives output rejection, cancellation and content deletion; unknown actual usage remains absent. The circuit breaker is intentionally instance-local, not a cross-instance availability claim.
